# RealmOS — Product Principles v1

## 1. Make the User Feel in Command

The system should feel powerful but not out of control.

## 2. Every Project Becomes Alive

A project should not feel like a folder.  
It should feel like a small company with people/agents, memory, tasks, and direction.

## 3. Approval Should Feel Like Control, Not Friction

Approvals should be clear, fast, and informative.

## 4. Memory Should Feel Useful, Not Creepy

Jarvis should remember what helps, and let the user review/delete.

## 5. Agents Need Personality, But Also Discipline

Agents can have names and flavor, but must produce structured work.

## 6. The Dashboard Is the First Game Board

Before characters move around, the dashboard should already show a living system.

## 7. The World Map Is a Visualization, Not the Database

The real source of truth is the data model.  
The world map renders it.

## 8. Build for One Power User First

The first customer is Idan.

## 9. Treat It Like a Future Company

Even if personal, the architecture should support future productization.

## 10. Safety Is a Feature

Governance, audit, approval, and cost control are not side features. They are the foundation.
