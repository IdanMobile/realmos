# RealmOS — Agent Taxonomy v1

## Global Agents

### Jarvis

Main assistant, command interface, user conversation, routing, memory recall, system briefing.

### Government

Rules, approvals, budget policy, forbidden actions, permission system, audit enforcement.

### Necromancer

Agent creator, optimizer, tester, lifecycle manager.

### Council

Debate and strategic review system for complex or uncertain decisions.

### Guards

Protectors of the realm. Security, privacy, access control, risk scanning.

### Memory Keeper

Manages memory scope, summaries, retention, and deletion/review.

### Auditor

Reviews logs, mistakes, costs, decisions, and risky actions.

### Archivist

Maintains decisions, specs, documentation, history, and long-term knowledge.

### Dispatcher

Routes tasks to correct business, agent, or Council.

### World Map Visual Agent

Owns visual representation only. Reads world contract and suggests/updates visual layout, rooms, lands, agent placement, and future game-like presentation.

## Agent Lifecycle

1. Proposed
2. Designed
3. Tested
4. Approved
5. Active
6. Reviewed
7. Improved
8. Retired

## Rule

Agents are not created randomly.

Necromancer must answer:

- Why is this agent needed?
- Can an existing agent do this?
- What tools does it need?
- What memory can it access?
- What are its limits?
- Who supervises it?
- How is performance measured?
